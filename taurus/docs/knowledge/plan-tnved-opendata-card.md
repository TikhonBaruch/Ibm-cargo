# План: открытые данные ТН ВЭД → одна карточка

**Дата:** 2026-08-15.  
**Цикл D33.** План **до кода**. Каждый слой — отдельный цикл (ETL → проверка → KB).  
Канон: [`data-model.md`](./data-model.md) §2 · [`customs-payments.md`](./customs-payments.md) · [`plan-tnved-demo-corpus.md`](./plan-tnved-demo-corpus.md) · [`plan-client-tnved-search.md`](./plan-client-tnved-search.md) · D15 (брокер подтверждает код) · D32 (карточка = drawer / тот же combobox, не новый кабинет).

**Идея.** Коммерческие Такса/TKS показывают «всё в одной карточке», потому что **сами склеили** официальные слои. Слои уже **открытые**, просто разрозненные (PDF, `TNVED.7z`, JSON). Мы клеим их легально: скачать → нормализовать → `TnvedCode` + `TnvedDutyRate` → одна карточка в UI.

Скрейп HTML Альты / TKS / CustomsOnline **не нужен** и запрещён. Скачивание госнаборов и PDF ЕЭК — разрешено.

```text
сырой файл (opendata)
  → нормализатор (наш, в scripts/)
  → слой в Postgres
  → GET /v1/tnved/:code  = карточка
  → клиент / брокер / админ
```

Демо ([`plan-tnved-demo-corpus.md`](./plan-tnved-demo-corpus.md)) = **срез той же трубы** (~50 листьев must-cover), не второй выдуманный справочник. Полное дерево — те же скрипты, чанки >500.

## Карточка (целевой envelope)

Один код = одна карточка. Поля копятся по слоям; пустое = `null` + «нет в источнике», не выдумка.

| Блок карточки | Слой | Источник (легальный) | Когда |
|---------------|------|----------------------|--------|
| Код, display, уровень, предки | A дерево | ФНС [`TNVED.7z`](https://www.nalog.gov.ru/rn77/program/5961290/) (актуальность на странице) | срез 1 |
| Официальное `titleRu` (+ даты действия) | A | тот же архив `TNVED1`–`TNVED4` | срез 1 |
| Пошлина ЕТТ (`dutyKind`, `%` / специфич.) | B тариф | ЕЭК **СТНВЭДСТ** (решение Коллегии **№ 113**, открытый доступ) · запасной машиночитаемый: [data.egov.kz JSON/Excel](https://data.egov.kz/datasets/view?index=euraziyalyk_ekonomikalyk_odakt) (ЕТТ, обновление 2026-05-08) | срез 2 |
| НДС 22% / сбор ПП 1637 | C платежи РФ | уже в коде ([`customs-payments.md`](./customs-payments.md)) — **не** из классификатора | срез 2 (подмешать в карточку) |
| Пояснения (выдержка) | D текст | PDF пояснений ЕЭК (PSN), сначала только must-cover | срез 3 |
| Решения о классификации ЕЭК | E | страница решений ЕЭК (таблица PDF/HTML официальная) | hold / срез 5 |
| НДС 10% перечень | F | ПП РФ № 908 и смежные | hold (как в customs-payments) |
| НТМ / акциз / утиль | G | префиксы НК 181, ПП 1291/81, главы ЕЭК (триггер, не ставка) | срез 4 |

Дисклеймер на карточке: рекомендация справочника, финал — брокер / таможенный орган (D15).

Юридический эталон формулировок: Решение Совета ЕЭК **№ 80** (PDF по группам на [странице ЕТТ](https://eec.eaeunion.org/comission/department/catr/ett/)) — сверка, не runtime.

**Не источник карточки:** opendata ФТС `list.csv` (это **статистика** торговли по кодам, не номенклатура). TKS / Альта / tnved.info.

## Срезы (поэтапная компоновка)

Каждый срез: план уже здесь → код ETL или UI → `test:ci` → Hobby (migrate если схема) → KB.

### Срез 0 — манифест источников (без импорта в прод-БД)

Файл `scripts/data/tnved/manifest.json`:

- ФНС TNVED.7z + дата актуальности + описание структуры TXT  
- ЕЭК № 113 / НСИ СТНВЭДСТ  
- data.egov.kz dataset id + дата renewal  
- URL PDF ЕТТ / пояснений  

Скрипт `tnved:fetch` качает в `raw/` (ручной запуск, не CI). Не ходить на TKS.

**Готово:** по манифесту можно повторить выгрузку; checksum совпал.

### Срез 1 — слой A, дерево (первый код данных)

1. Парсер `TNVED*.TXT` (DOS/cp866) → нормализованный JSONL: `code`, `titleRu`, `level`, `parentCode`, `validFrom`/`validTo`, `isLeaf`.  
2. Upsert в `TnvedCode` **чанками** (обход лимита HTTP 500: CLI `prisma`/domain `upsertTnvedBatch`, не браузер).  
3. Для демо: фильтр must-cover из [`plan-tnved-demo-corpus.md`](./plan-tnved-demo-corpus.md) → `demo-pack.json` **из этого JSONL**, официальные имена.  
4. Поиск: `titleRu` + `notes`.

Проверка: число листьев ≫ 9; «8471 30 000 0» = официальное наименование, не «ноутбук»; предки без заглушки `Позиция ТН ВЭД`.

### Срез 2 — слой B+C, тариф + платежи РФ → карточка API

1. Парсер ЕТТ (приоритет: НСИ/№ 113; иначе JSON Казахстана) → `TnvedDutyRate` + `source`. Нет ставки → `null`.  
2. Расширить `GET /v1/tnved/:code` (dual-path + [`d-tnved.core.json`](../contracts/d-tnved.core.json) bump):

```text
code, codeDisplay, titleRu, titleEn?,
ancestors[],
rate { dutyKind, dutyPct, dutyRubPerUnit, source },
paymentsHint { vatPct: 22, feeRule: "ПП 1637" },  // не колонка ЕТТ
sources[] { layer, url, asOf },
disclaimer
```

НДС и сбор **не** брать из дампа ФНС (их там нет).

### Срез 3 — UI одной карточки

Паттерн D32: **slide-over** `VedDetailDrawer` (как заявка), не новая страница.

- Клиент: выбор в combobox → можно открыть карточку (полное имя, предки, пошлина, НДС/сбор-hint). `hsHint` по-прежнему черновик.  
- Брокер: клик по коду в WorkMapping → та же карточка (ставки уже частично через `onHint`).  
- Админ `/tnved`: поиск → та же карточка.

Не обрезать `titleRu`. Не обещать НТМ.

### Срез 4 — слой D, пояснения (сначала демо-листья)

Текстовая выжимка из PDF ЕЭК в `notes` или отдельное поле `explanation` (если notes заняты синонимами — лучше колонка/`attrs` JSON на коде, не путать с product attrs). Только must-cover, не 97 групп сразу.

## Готово (после среза 3)
