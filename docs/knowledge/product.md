# LBM Брокер — продукт

Источники: `Таурус/Проект- Карго Брокер AI.txt`, `Таурус/КАРГО БРОКЕР.pdf`, `Таурус/AI-платформа…дорожная карта.pdf`.

## Vision

AI-платформа управления импортом и ВЭД (не сайт брокера). AI — первая линия; брокер подтверждает. Ценность: **уверенность в стоимости импорта до оплаты поставщику**.

## Фокус MVP: частный заказчик (D27)

Целевой сценарий удобства (idea-check / polish) — **не** enterprise ERP и **не** «доставка под ключ» как текущий deliverable.

| Шаг | Что ищет клиент | Что продаём сейчас | Временно вне продукта |
|-----|-----------------|--------------------|------------------------|
| 1 | ТН ВЭД + смета платежей | heuristic draft + attrs (D24), confidence, дисклеймер | LLM-сопоставление «без кода» |
| 2 | Контролёр качества (брокер) | STANDARD/PRO → pay → queue → claim → chat → approve | — |
| 3 | Итог до поставщика | PDF после `DONE` | — |
| 4 | Доставка под ключ | **не обещать в CTA**; next-step позже | внешняя логистика / shipping UI |

**Формула:** частник получает черновик ТН ВЭД и смету → за тариф — проверку брокером и PDF; «под ключ» — после реального 3PL.

Persona / ценность / стратегия (производитель, master-data, buyer-groups): [`target-client.md`](./target-client.md) · ADR **D29**.

Граница исполнения: [`plan-mvp-polish.md`](./plan-mvp-polish.md) (без logistics / LLM / ЮKassa). Mock topup + heuristic остаются рабочим путём.  
**Навигация и копирайт лендинга (D27):** CTA → `/login` \| `/register`; hero / тарифы Экспресс·Стандарт·Профи / сценарий ТН ВЭД→брокер→PDF — в [`src/components/landing/`](../../src/components/landing/). Полная база ТН ВЭД, LLM enrich и shipping UI — **hold** ([`calculation-fields.md`](./calculation-fields.md) §4).

## Роли

| Роль | Задачи |
|------|--------|
| Клиент (импортёр) | Просчёты, брокеры, завод/сборка, баланс, поддержка. Сегмент компании: розница / единичные / опт (D34), не три UserRole |
| Брокер | Очередь оплаченных заявок, правка ТН ВЭД, чат, SLA ≤ 4 ч, выплаты |
| Админ платформы | Заявки, клиенты/брокеры, тарифы, финансы, AI-качество, audit |
| Сотрудник производителя (D31/D34) | Эталонные SKU + подтверждение сборного заказа в `/manufacturer` (инвайт ADMIN); не CTA лендинга |

## Клиентский flow

**MVP (D27):** товар (+ attrs) → heuristic AI → код + платежи → оплата тарифа → очередь брокера (QC) → подтверждение → **PDF**.  
**Vision (позже):** … → перевозка / оформление «под ключ».

Товар/документы → AI → код + платежи → оплата тарифа → очередь брокера → подтверждение → PDF → (опц.) перевозка / оформление.

## Roadmap

MVP (калькулятор + брокер + PDF) → Growth (OCR, консультант, KB) → Platform (API, MLOps) → Ecosystem (marketplace, ERP, голос, **консолидация объёмов / buyer-groups** — D29).

Контейнерная стратегия по фазам (не as-is): MVP = текущие 14; Growth = **углубить** notify/worker/ai/logistics/payments + **`containers/ocr`** (P2); Platform = observability / pdf / Redis broker по нагрузке. Детали: [`../containers.md`](../containers.md), [`containerization.md`](./containerization.md).

Целевой клиент и ценность (MVP + стратегия): [`target-client.md`](./target-client.md).

## Правила

- Без оплаты заявка не в очередь брокера (D11). Live — без «1 бесплатно» (C29); freemium только lab / явный non-prod gate.  
- Окончательное решение — брокер / клиент; AI — рекомендация + дисклеймер.  
- Сплит: платформа ~60–70% / брокер ~30–40%.
