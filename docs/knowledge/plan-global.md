# Глобальный план: от поиска ТН ВЭД к полной площадке

**Дата:** 2026-08-15.  
**Цикл D33.** Этот файл — **план до кода** (горизонт, не один PR). Каждый этап — отдельные циклы: план среза → реализация → `test:ci` → Hobby → KB.  
Канон: [`feature-cycle.md`](./feature-cycle.md) · [`product.md`](./product.md) (D27) · ADR D26 / D32 / D33 / D34.  
Детализация срезов: [`plan-ai-mesh.md`](./plan-ai-mesh.md) · [`plan-ocr-vision.md`](./plan-ocr-vision.md) · [`plan-precedent-bulk.md`](./plan-precedent-bulk.md) · [`plan-cabinets-d32.md`](./plan-cabinets-d32.md) · [`plan-newcalc-hints.md`](./plan-newcalc-hints.md).  
**Активный срез (pay-first / cascade / C31):** [`plan-next-vector-c28.md`](./plan-next-vector-c28.md) · [`plan-classify-cascade-c23.md`](./plan-classify-cascade-c23.md).

Брокер из процесса **не исчезает**. Код скрытых поверхностей **не удалять**: прятать флагами, как перевозка (`cabinet-features.ts` / `NEXT_PUBLIC_SHIPPING_UI`).

```text
этап 1  кабинеты готовы, наружу — поиск ТН ВЭД
этап 2  простые + векторные базы, ИИ: сначала онлайн, потом офлайн
этап 3  полный конвейер как на схеме (или уточнённый аналог)
этап 4  фото + страница товара по ссылке
этап 5  снять флаги, собрать окончательный продукт
```

## Сквозные правила

| Правило | Смысл |
|--------|--------|
| Кабинеты = правый край схемы | Человек видит черновик, правит, отдаёт PDF |
| Mesh = позвоночник слева | Пакет → распределитель → параллельные расшифровки → сводка → брокер |
| D27 жив до этапа 5 | Heuristic/поиск ТН ВЭД → оплата → очередь → PDF |
| Скрыто ≠ вырезано | Factory, сборные, перевозка, фото, ссылка — код остаётся, UI off до своего этапа |
| Dual-path | Любая мутация ядра — Next **и** `containers/api` |
| Не скрейпить Alta / TKS / CustomsOnline | Справочник — свой корпус + позже лицензионный KEY |

## Этап 1. Кабинеты окончательного формата, наружу — поиск ТН ВЭД

**Идея.** Собрать четыре кабинета (клиент, брокер, админ, завод) в **финальной оболочке**: те же nav, empty/loading/error, drawer, тосты. На ближайшие сессии в работе только **поиск и выбор ТН ВЭД**. Остальной уже написанный контур (завод, сборные, смета без фрахта, перевозка) остаётся в коде и **скрыт**. Когда заработает схема этапа 3, скрытое возвращается флагами — без второй сборки UI.

**Зачем так.** Рынок сначала должен получить ясный код и смету. Расширение входов и завода без живого поиска ТН ВЭД даёт «много кнопок» и слабый черновик.

**Уже есть.** Брокер: `HsCodeAutocomplete` → `GET /api/v1/tnved/search`. Админ: импорт + поиск в справочнике. Клиент: heuristic `HsHintCandidates` **и** combobox справочника на NewCalc (`leafOnly`, `attrs.hsHint`) — [`plan-client-tnved-search.md`](./plan-client-tnved-search.md) срез 1. **Слой A ФНС (срезы 0–1):** манифест + `tnved:fetch/normalize/load`, демо-пакет из официальных TNVED4 (не ярлыки seed), поиск по `titleRu` **и** `notes`.

**Ближайшие сессии (только это):**

1. Клиентский combobox ТН ВЭД по справочнику Postgres (тот же паттерн, что у брокера) — не LLM-кнопка «угадай код». План UI: [`plan-client-tnved-search.md`](./plan-client-tnved-search.md).
2. Качество поиска: название RU, код, синонимы; пустой результат с одним CTA «описать товар своими словами».
3. Подсказка heuristic top-N рядом с поиском: «почему эти коды», без обещания финала.
4. Админ: корпус в `TnvedCode` достаточный для демо. Пакет+seed+карточка **live**. ЕТТ-ставки — `null` (KZ opendata v3 без цифр). Флаги завода: [`plan-cabinet-feature-flags.md`](./plan-cabinet-feature-flags.md).
5. Флаги скрытия: расширить `src/lib/ved/cabinet-features.ts` по аналогии с `shippingUiEnabled` — завод / сборные / перевозка / лишний вход «фото-ссылка» off, маршруты не удалять. План: [`plan-cabinet-feature-flags.md`](./plan-cabinet-feature-flags.md). Смету без фрахта **не** прятать (D27).

**Кабинеты «окончательного формата» в этом этапе — каркас, не CTA:**

| Кабинет | Формат готов | В ближайших сессиях трогать |
|---------|----------------|-----------------------------|
| Клиент | дашборд, новый просчёт, PDF, чат, баланс | только форма просчёта + поиск HS |
| Брокер | очередь, mapping, autocomplete HS, чат, approve | поиск/QC кода, не новые panes |
| Админ | ops / каталог / платформа | импорт ТН ВЭД, не CMS |
| Завод | SKU / спрос / пулы **уже в коде** | **скрыть** до этапа 5 (или до конца этапа 3) |

**Готово, когда:** клиент находит код по названию, брокер подтверждает из того же справочника, PDF после оплаты жив, скрытые пункты nav не светятся, `smoke:mvp` зелёный.

**Не делать в этапе 1:** mesh, GPU, фото, парсер ссылок, включение перевозки, публичный signup завода/брокера.

## Этап 2. Базы и ИИ: сначала онлайн, потом офлайн

**Идея.** Две памяти + три расшифровки. Простые базы — сразу. Вектор — когда есть ключ эмбеддингов. Параллельный вызов моделей — сначала облако, локальные модели — когда ясен хост и GPU.

### Две базы

| База | Что хранит | Сейчас | На этапе 2 |
|------|------------|--------|------------|
| **Простая** | Листья ТН ВЭД (`TnvedCode` + `codes.jsonl`), ставки пошлины, прецеденты lexical (`verified_determinations`) | live / partial | довести импорт, поиск, write-back с approve брокера (уже есть путь) |
| **Векторная** | эмбеддинги описаний и одобренных решений (`precedent-v2`, pgvector) | hold D30 | включить, когда есть embedding-ключ; порог cosine; без ключа — lexical |

Не вторая Postgres на Hobby. Вектор — расширение той же БД (`pgvector`), не отдельный кластер. Канон прецедентов: [`plan-precedent-bulk.md`](./plan-precedent-bulk.md) · [`data-model.md`](./data-model.md) §2.2.

### Подключение ИИ

Порядок жёсткий: **онлайн → офлайн**. Не наоборот.

1. **Онлайн (начало):** `containers/llm` classify/duty по API (OpenAI-совместимый / NIM). Fail-open: нет ключа → lookup по корпусу → heuristic. Create заявки не падает.
2. **Параллель (после среза 1 mesh):** на create три `ServiceCall` `ocr` / `ai` / `llm` сразу, видно в `/admin/orch`. Пока ocr без фото — stub или text-PDF.
3. **Офлайн (потом):** локальная «рабочая» модель (Ollama / свой хост) как вторая колонка схемы. Тестовая третья колонка — песочница, не CTA.

### Ресурсы: что обсудить в ближайшее время

Отдельная сессия **до** большого кода этапа 2.

| Когда | Нужно | Зачем | Чего не брать сразу |
|-------|--------|--------|---------------------|
| **Сейчас (этап 1–2 старт)** | Текущий Vercel Hobby + одна Postgres | Кабинеты, поиск HS, heuristic | GPU, второй Postgres, Cron чаще daily |
| | Ключ **онлайн-классификатора** (`OPENAI_API_KEY` или NIM) | Параллельный `llm` без своего железа | «Все модели мира» |
| | Диск под корпус `codes.jsonl` (~13k листьев; полный dump — позже) | Поиск и lookup | Скрейп энциклопедий |
| **Следом (вектор)** | Тот же ключ **с embeddings** + расширение `pgvector` на той же БД | precedent-v2, меньше повторных ошибок | Отдельный Pinecone/Weaviate |
| | Лимит токенов / cost cap в админке | Не сжечь ключ на демо | Безлимитный enrich на лендинге |
| **Потом (офлайн + этап 4)** | Хост с RAM 16–32 GB; GPU — если локальная 7–14B | Вторая расшифровка без облака, приватность документов | GPU на Vercel Hobby (его нет) |
| | Vision-модель (отдельная от instruct) | Этап 4 фото | Одна модель «и текст, и зрение» вслепую |
| | Fetch страниц (прокси, timeout, robots) | Этап 4 ссылка | Парсинг WB/Ozon в этапе 1–2 |

Compose `scale`/`full` — лаборатория (ocr, llm, worker). Прод Hobby остаётся web+Postgres, пока нет ADR на отдельный GPU-хост.

**Готово, когда:** простой поиск и lexical-прецедент работают без ключа; с ключом — онлайн classify в параллели с heuristic; вектор opt-in; офлайн — отдельный хост, не блокер этапа 3.

## Этап 3. Полная внутренняя обработка запроса

**Идея.** Реализовать схему «логистов» (или более жёсткий аналог): вход кладётся в хранилище → распределитель → несколько независимых расшифровок → **один** формат запроса → ТН ВЭД + RAG → брокер → клиент + обратная связь.

Канон срезов: [`plan-ai-mesh.md`](./plan-ai-mesh.md). Целевой контур этапа 3:

```text
форма / Excel / (позже фото и URL)
  → пакет в БД + файлы
  → распределитель (job AI_DRAIN, не новый FSM)
      ├ онлайн LLM
      ├ локальный heuristic / офлайн-модель
      └ тестовая колонка (hold, тег engine)
  → unify: attrs + кандидаты HS + инвойс/смета без фрахта + SKU завода если есть
  → RAG: сначала прецедент, потом корпус ТН ВЭД
  → AI_READY → оплата → брокер QC → PDF
  → approve пишет прецедент обратно
```

Уточнение схемы (намеренно более проработано, чем исходный чертёж):

- Статусы заявки **не** плодить: D8 остаётся. Mesh живёт в `BackgroundJob` / `ServiceCall` (D26).
- «Посредник исчезает» = только узкий Express auto-DONE при высокой уверенности и повторе SKU. Роль брокера на площадке навсегда.
- Excel уже вход. Почта/Telegram — тот же пакет, не второй пайплайн, и только после позвоночника.
- Сводка одна: брокер не читает три сырых ответа моделей, а один envelope.

**Готово, когда:** create даёт единый пакет, orch показывает три вызова, брокер видит сводку, PDF как сейчас, fail-open без ключей, кабинеты не переписаны.

После этого **возвращается скрытый функционал этапа 1**, который зависит от ядра: заводской SKU в просчёте, спрос, сборные пулы, смета без фрахта на карточке. Перевозка по-прежнему не CTA, но может остаться за своим флагом до этапа 5.

## Этап 4. Картинки и страницы по ссылке

**Только после** живого этапа 3 (и стабильного этапа 1 по ТН ВЭД). Иначе фото/URL — отдельный бот, как у конкурентов, без брокера и PDF.

Два входа в **тот же** пакет, не новый продукт:

| Вход | Что делает | Опора |
|------|------------|--------|
| **Фото** | Инвойс / этикетка / карточка → attrs и позиции | [`plan-ocr-vision.md`](./plan-ocr-vision.md): API `imageBase64` уже в `containers/ocr`; нет UI. Сначала таблица с инвойса (OCR-A), потом фото товара (OCR-B) |
| **Ссылка** | WB / Ozon / аналог → название, цена, описание, фото | Нет кода. Нужны: fetch HTML, нормализация в тот же unify, дисклеймер «карточка ≠ инвойс», timeout, уважение robots, без скрейпа справочников ТН ВЭД |

Порядок внутри этапа 4: фото инвойса → фото товара → ссылка. Ссылка без unify этапа 3 снова превратится в «посчитал в чате и забыл».

**Готово, когда:** клиент кладёт JPEG или URL на `/cabinet/new`, пакет тот же, брокер видит источник («фото» / «ссылка»), create fail-open без vision-ключа, нет CTA «распознай без брокера».

## Этап 5. Полная сборка окончательного проекта

Снять согласованные флаги. Собрать один продукт: прозрачный контур до оплаты поставщику.

**В составе:**

- Поиск и черновик ТН ВЭД + смета платежей (без смешения с чужим фрахтом).
- Параллельные модели + сводка + прецеденты.
- Именованный брокер, SLA, PDF.
- Завод: эталон SKU, спрос без чужих ПДн, сборный объём.
- Входы: форма, Excel, фото, ссылка.
- Админ: ключи не в UI, orch, качество AI, справочник.
- Клиент свободен после PDF: банк и 3PL — партнёры, не захват сделки.

**По-прежнему не «окончательный» в смысле чужих продуктов:** live-эквайринг, свой банк, «привезём под ключ» как главный CTA, LLM без кода на лендинге, slim-web на Vercel без ADR.

**Готово, когда:** ручной сценарий C↔B↔A↔завод на staging: ссылка или фото → код → оплата → брокер → PDF → (опц.) запрос в пул завода; `test:ci` + узкий smoke; KB и контракты совпадают с кодом.

## Ближайшие сессии vs горизонт

```text
сейчас     этап 1: поиск ТН ВЭД + флаги скрытия лишнего
скоро      совещание по ресурсам этапа 2 (таблица выше)
затем      этап 2 онлайн + простые базы; вектор и офлайн — по ключу/хосту
затем      этап 3 mesh (срезы 1–2 обязательны, 3–5 по готовности)
потом      этап 4 фото и ссылка
в конце    этап 5: открыть скрытое, один контур
```

Тонкость: **не строить завод и фото раньше, чем код находится**. Когда схема заработает, скрытые кабинеты включатся в уже знакомую оболочку — прозрачность рынка (трасса решения, брокер с именем, эталон завода) появляется целиком, а не кусками бота.
