## Идея

На карточке и в поиске показать **развилки классификации** (не путать / вариант / целое↔части / комплект инвойса). Дерево `parentCode` уже в Postgres. **Не** заводить junction-таблицу и **не** выдумывать листья.

## Анализ (as-is)

| Слой | Факт |
|------|------|
| `TnvedCode.parentCode` | FK живой: 0 сирот; главы без parent = 0. Карточка уже рисует **предков**. |
| Дети | в БД есть (`children of 8471` = 14), на карточке **не** отдавались |
| C19 notes | текст «не путать» есть, но нет кликабельного связанного кода |
| Инвойс | charger↔powerbank, T恤↔поло, smartwatch↔кварц — разные главы, дерево их не связывает |
| ФТС 641 | 8543 40 ↔ 8543 90 (спираль vs картридж без катушки) |

Не делать: scrape Альта/TKS; `tnved:load -- --full`; Prisma migrate под рёбра (~20 curated edges).

## Структура

1. `tnved-relations.json` — направленные рёбра `from→to` на **существующих** кодах (`not` / `variant` / `part` / `kit`).
2. `GET /v1/tnved/:code` — `related[]` из JSON + `children[]` из `parentCode` (лимит 16). Dual-path.
3. `--search-extras` дописывает why + цифры связанного кода в `notes` (поиск находит оба).
4. UI: `/cabinet/tnved` чипы «Не путать / Вариант»; drawer `TnvedCodeCard` — список.

`kit` = типичные строки одного инвойса, **не** юридическая зависимость ТН ВЭД.
