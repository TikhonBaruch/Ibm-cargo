# План: корпус ТН ВЭД для демо (не Track B)

**Дата:** 2026-08-15.  
**Цикл D33.** План **до кода**. Этап 1 [`plan-global.md`](./plan-global.md) («Админ: корпус достаточный для демо»).  
Канон UI: **D32** — тот же экран `/admin/tnved` ([`plan-admin-tnved-ui.md`](./plan-admin-tnved-ui.md)): chips, preview, toast, empty. Не новое дерево всех кодов.  
Связано: [`plan-client-tnved-search.md`](./plan-client-tnved-search.md) · [`plan-tnved-opendata-card.md`](./plan-tnved-opendata-card.md) (легальные слои → карточка) · [`data-model.md`](./data-model.md) §2.1 · [`cabinets/admin/`](./cabinets/admin/).

**Цель:** клиентский combobox находит код по бытовому названию в **демо**. Не полный классификатор РФ.  
**Качество (жёстко):** по каждому коду в пакете — **максимально точные, корректные и подробные** данные ТН ВЭД. Узкий охват ≠ урезанные строки. Лучше 50 полных листьев, чем 50 коротких ярлыков.

## Идея

Два слоя ТН ВЭД не сливать:

| Слой | Где | Для чего |
|------|-----|----------|
| **DB catalog** (`TnvedCode`) | Postgres, UI search | Клиент / брокер / админ combobox |
| **Corpus jsonl** (~13k) | `containers/llm`, часто **нет в этом репо** | lookup-v1 classify, не UI |

Демо живёт в **DB**. Сейчас seed — 9 листьев под heuristic-v1. Combobox «кроссовки / наушники / игрушки» пустой. Полный dump и скрипт `tnved:export-import` (упомянут в data-model, **в package.json нет**) — Track B / этап 2, не этот цикл.

Корпус для демо = **кураторский пакет ~40–80 листьев** в репозитории: покрывает правила AI + типичный мелкий импорт. Влезает в лимит `POST /tnved/import` (≤500). Каждый лист — полный досье-ряд (ниже), не «смартфон» в одну строку.

Поиск UI: `titleRu contains` + префикс кода. Синонимы = слова **в** `titleRu` / `notes` (отдельной таблицы нет).

## Что интегрируем (готовые фичи)

| Фича | Откуда | Как |
|------|--------|-----|
| Экран импорта | `TnvedImportPane` | Не новый URL; сверху — KPI + демо-CTA |
| Batch upsert | `POST /api/v1/tnved/import` | Демо-пакет одним `items[]` |
| CSV preview | `parseTnvedCsv` + таблица как сейчас | Превью пакета до «Импортировать» |
| Поиск «уже в справочнике» | тот же блок | После импорта проверить «кроссовки» |
| Toast | `VedToast` (уже на import) | «Загружено N листьев» |
| Empty | `VedEmptyState` / amber-строка | Мало кодов: одна CTA «Загрузить демо-набор» |
| Предки кода | `hsCodeAncestors` | Seed и import уже умеют |
| Список must-cover | `ai-draft-rules.json` + `EXPAND` в `tnved-lookup.js` | Те же бытовые слова, что heuristic / llm |
| Chips режимов | single / CSV / JSON | Четвёртый chip **не** плодить; демо — кнопка в шапке карточки «Справочник» |

Клиентский combobox ([`plan-client-tnved-search.md`](./plan-client-tnved-search.md)) **потребляет** этот корпус; сам пакет собираем в seed + админке. UI поиска обязан **показывать** поля пакета (полное наименование, код с пробелами, предки, ставка), а не обрезать до ярлыка.

## Качество данных (обязательно)

Требование к демо то же, что к прод-справочнику: пользователь и брокер видят **максимально точные, корректные и подробные** сведения по ТН ВЭД. Демо режет *число* кодов, не *глубину* строки.

| Поле | Как делать | Не делать |
|------|------------|-----------|
| `code` / `codeDisplay` | 10 знаков листа; отображение `8471 30 000 0` | выдуманные/укороченные коды |
| `titleRu` | **Официальная** формулировка номенклатуры (ЕАЭС / наш корпус), полностью | маркетинг «Смартфоны»; смесь синонимов в title |
| `titleEn` | Если есть в источнике — заполнить | пустой EN «чтобы быстрее» |
| Предки 2/4/6/8 | Реальные названия глав/позиций через `hsCodeAncestors` | заглушка `Позиция ТН ВЭД 8471` как в текущем seed |
| `notes` | Бытовые синонимы, уточнения (материал, назначение), оговорки по коду | портить `titleRu` скобками «кроссовки» |
| Ставка | `dutyKind` + `dutyPct` / specific **как в каноне корпуса**; НДС **22%** ([`customs-payments.md`](./customs-payments.md)); сбор ПП 1637 в `feeHintRub` если известен | угадать пошлину «как heuristic»; оставить 20% НДС |
| `source` | Явная метка источника (`seed-demo-pack` + откуда взята ставка) | пустой source |
| Неизвестно | `null` + пометка в notes | вымышленная цифра «для красоты» |

Поиск: `titleRu contains` **и** `notes contains` (иначе синонимы в notes не находятся) — правка `searchTnvedCodes` в том же срезе, что пакет.

Юридически: рекомендация, не финал таможни (дисклеймер как у draft). Точность пакета = не врать в справочнике. Скрейп Alta / TKS / CustomsOnline запрещён. **Официальные выгрузки** (ФНС TNVED.7z, ЕТТ/НСИ, JSON Казахстана) — канон сборки: [`plan-tnved-opendata-card.md`](./plan-tnved-opendata-card.md). Демо-пакет = срез той же трубы, не выдуманные title.

## Состав демо-пакета (курация)

Узкий набор листьев, по которым ищут в демо — **каждый** с полным досье выше:

1. **Уже в seed / heuristic:** ноутбук, смартфон, брюки, автозапчасти, краска, шоколад, мебель, БП/преобразователь, клавиатура — **переписать** с коротких seed-title на официальные.
2. **Добавить (типичный частник / WB-Ozon):** обувь (6404), сумки (4202), игрушки (9503), косметика (3304), наушники (8518), часы (9102), посуда (6911), крепёж/инструмент (7318 / 8204), LED/лампы (8539), аккумуляторы (8507), кабель (8544), упаковка/пакеты (3923).
2b. **Clar-DB (2026-09-02):** погрузчики **8427** (электро `8427101000`, ДВС `8427201900`) + notes; 8507 notes разводят тяговый АКБ ≠ машина. План: [`plan-ai-clarify-db-boost.md`](./plan-ai-clarify-db-boost.md).
3. **Синонимы** — только в `notes` (кроссовки, кеды, sneakers…). `titleRu` не сокращать.
4. **Ставки** — из канона/корпуса; нет данных → `null`, не heuristic-угадайка.

Объём: **порядка 60 листьев** (+ предки). Меньше 500. Не 13k.

Файл в репо: `scripts/fixtures/tnved/demo-pack.json` в форме `{ items: TnvedImportItem[] }` — тот же shape, что JSON-режим админки. Seed читает тот же файл (один источник правды).

## Структура UI (`/admin/tnved`)

Паттерн: **сводка каталога + одна CTA**, не wizard.

```text
карточка «Справочник в системе»
  KPI: N позиций · M листьев     # GET search не даёт count — см. срез 1
  StatusPill: «Демо» если M < порога (напр. 40)
  [ Загрузить демо-набор ]       # preview → confirm тем же onImport
  поиск как сейчас
  empty поиска: «Нет в справочнике» + CTA на демо, если каталог тонкий
```

Режимы форма/CSV/JSON **не трогать** по смыслу. CSV-sample в UI расширить 2–3 строками из пакета (обувь, наушники), не всем файлом.

Клиент NewCalc (срез 2 client-search): если 0 хитов — copy «В демо-справочнике нет этой формулировки. Опишите товар или другой запрос.» Не обещать полный ТН ВЭД.

## Срезы

### Срез 1 — пакет + seed (первый код)

1. Фикстура `demo-pack.json`: ~50 листьев, **официальный** `titleRu` (+ `titleEn` при наличии), `notes` с синонимами, полная цепочка предков, ставки с `source` (НДС 22%; пошлина не выдумывать).
2. `seedTnvedDirectory` импортирует пакет (не дублировать 9 урезанных листьев вручную).
3. `searchTnvedCodes`: искать по `titleRu` **или** `notes`.
4. Админ: KPI count (достаточно `GET /api/v1/tnved/search?q=` не умеет — **минимальный** `GET …/tnved/stats` `{ total, leaves }` или reuse search с широким q; предпочтительно маленький stats, dual-path).
5. Кнопка «Загрузить демо-набор»: fetch фикстуры **из бандла** (import JSON в pane) → preview table (код, полное имя, ставка) → `onImport`. Не качать jsonl с диска сервера (на Vercel файла нет).
6. Combobox / админ-поиск: в списке и после выбора — полное наименование, не обрезанный ярлык (срез UI; брокер уже показывает `titleRu`).

Проверка: после seed «кроссовки» бьёт в notes обуви; карточка/выпадашка показывает полный `titleRu` и ставку; нет заглушек `Позиция ТН ВЭД …`; `test:ci`; ручной `/admin/tnved` и `/cabinet/new`.

### Срез 2 — empty / честный объём

- `VedEmptyState` или amber, если листьев < 40: why + одна CTA «Загрузить демо-набор».
- Клиентский no-hits copy (вместе с [`plan-client-tnved-search.md`](./plan-client-tnved-search.md) срез 2).
- Не показывать «полная база РФ».
- Честно: мало **кодов**, но каждый показанный код — полный и проверенный.

### Срез 3 — hold

| Тема | Почему |
|------|--------|
| Импорт всего `codes.jsonl` (~13k) | Track B; лимит 500; файла нет в Hobby-репо; нужен ops-скрипт чанками |
| `tnved:export-import` | Сначала появится jsonl в compose; отдельный цикл этапа 2 |
| Скрейп Alta / TKS / CustomsOnline | Запрет |
| Синонимы отдельной таблицей | Хватает titleRu для демо |
| Дерево / drawer ставок | Явно вне [`plan-admin-tnved-ui.md`](./plan-admin-tnved-ui.md) |
| Подмена heuristic кодами из пакета | Draft остаётся rules; пакет кормит **поиск UI** |

## Не делать

- Новый кабинет «классификатор».
- Обещать на лендинге «все коды ТН ВЭД».
- Грузить jsonl в браузер.
- Снимать лимит 500, чтобы протащить Track B «заодно».
- Второй экран импорта только для демо.
- Укорачивать официальное наименование «чтобы влезло в dropdown».
- Подставлять вымышленные пошлины, если в источнике нет ставки.

## Готово (срез 1)

После `prisma db seed` (и/или кнопки в админке) клиент и брокер находят демо-товары по-русски **и** видят полный корректный ряд ТН ВЭД (имя, предки, ставка, notes); админ видит, сколько листьев; полный dump по-прежнему hold.
